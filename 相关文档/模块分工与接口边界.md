# 模块分工与接口边界

## 1. 项目总体架构

MiniSQL 数据库管理系统分为三大模块，三人并行开发：

```
┌─────────────────────────────────────────────────┐
│           SQL编译器 (成员A)                       │
│  SQL文本 ──→ Lexer ──→ Parser ──→ Planner ──→ Plan │
└───────────────────────┬─────────────────────────┘
                        │ Plan 接口
                        ▼
┌─────────────────────────────────────────────────┐
│           数据库引擎 (成员B)                       │
│  Plan.open() ──→ Scan ──→ 结果集                   │
│  MetadataMgr (系统目录)                            │
│  JDBC 接口                                       │
└───────────────────────┬─────────────────────────┘
                        │ FileMgr/BufferMgr/Tx
                        ▼
┌─────────────────────────────────────────────────┐
│           存储系统 (成员C)                         │
│  Page ←──→ Buffer ←──→ FileMgr ←──→ Disk         │
│  LogMgr (日志)    Transaction (事务)               │
└─────────────────────────────────────────────────┘
```

## 2. 成员A — SQL 编译器

**职责**: 词法分析 → 语法分析 → 语义分析 → 执行计划生成 → 查询优化

### 文件清单

#### parse/ — SQL 解析器

| 文件 | 功能 | 说明 |
|------|------|------|
| `Lexer.java` | 词法分析器 | 将 SQL 文本拆分为 Token 流 |
| `Parser.java` | 语法分析器 | 递归下降解析，构建语法树 |
| `PredParser.java` | 谓词解析器 | 解析 WHERE 条件表达式 |
| `BadSyntaxException.java` | 语法异常 | 语法错误时抛出 |
| `CreateTableData.java` | CREATE TABLE 语义 | 存储建表语义信息（表名、字段、类型） |
| `CreateIndexData.java` | CREATE INDEX 语义 | 存储建索引语义信息 |
| `CreateViewData.java` | CREATE VIEW 语义 | 存储建视图语义信息 |
| `InsertData.java` | INSERT 语义 | 存储插入语义信息（表名、字段、值） |
| `DeleteData.java` | DELETE 语义 | 存储删除语义信息（表名、条件） |
| `ModifyData.java` | UPDATE 语义 | 存储更新语义信息（表名、字段、新值、条件） |
| `QueryData.java` | SELECT 语义 | 存储查询语义信息（字段、表、条件、分组、排序） |

#### plan/ — 执行计划生成器

| 文件 | 功能 | 说明 |
|------|------|------|
| `Planner.java` | 计划器总入口 | 统一调度查询和更新计划 |
| `Plan.java` | 执行计划接口 | 定义 `open()` 返回 Scan |
| `QueryPlanner.java` | 查询计划器接口 | |
| `UpdatePlanner.java` | 更新计划器接口 | |
| `BasicQueryPlanner.java` | 基础查询计划 | 简单的线性计划生成 |
| `BasicUpdatePlanner.java` | 基础更新计划 | |
| `BetterQueryPlanner.java` | 优化查询计划 | 基于代价的计划生成 |
| `TablePlan.java` | 表扫描计划 | 单表访问计划 |
| `SelectPlan.java` | 选择过滤计划 | WHERE 条件过滤 |
| `ProjectPlan.java` | 投影计划 | 字段选择 |
| `ProductPlan.java` | 笛卡尔积计划 | 多表连接基础 |
| `OptimizedProductPlan.java` | 优化笛卡尔积 | 带选择下推的连接 |

#### opt/ — 查询优化器

| 文件 | 功能 | 说明 |
|------|------|------|
| `HeuristicQueryPlanner.java` | 启发式查询优化 | 基于规则的多表连接优化 |
| `TablePlanner.java` | 单表计划优化 | 为单表生成最优访问路径 |

#### index/planner/ — 索引计划

| 文件 | 功能 | 说明 |
|------|------|------|
| `IndexJoinPlan.java` | 索引连接计划 | 利用索引加速连接 |
| `IndexSelectPlan.java` | 索引选择计划 | 利用索引加速查询 |
| `IndexUpdatePlanner.java` | 索引更新计划 | INSERT/DELETE 时维护索引 |

#### query/ — 查询表达式（编译期使用）

| 文件 | 功能 | 说明 |
|------|------|------|
| `Constant.java` | 常量值 | 支持 int 和 string |
| `Expression.java` | 表达式 | 字段或常量 |
| `Predicate.java` | 谓词 | WHERE 条件的组合（AND/OR） |
| `Term.java` | 比较项 | 单个比较表达式（=, <, > 等） |

### 模块输出接口

```java
// 编译器对外暴露的核心接口
public class Planner {
    Plan createQueryPlan(QueryData data, Transaction tx);
    int executeUpdate(UpdateData data, Transaction tx);
}

public interface Plan {
    Scan open();
    int blocksAccessed();
    Schema schema();
}
```

### 模块输入输出接口

```java
// 引擎调用编译器的 Plan

Transaction tx = new Transaction(fm, lm, bm);
TableScan ts = new TableScan(tx, "student", layout);
```

## 4. 成员C — 存储系统

**职责**: 磁盘 I/O、内存管理、日志系统、事务与并发控制

### 文件清单

#### file/ — 文件管理

| 文件 | 功能 | 说明 |
|------|------|------|
| `FileMgr.java` | 磁盘文件管理器 | 读写磁盘块，管理数据库目录 |
| `Page.java` | 内存页 | 磁盘块在内存中的映射，提供 get/set 方法 |
| `BlockId.java` | 磁盘块标识 | 由文件名 + 块号组成 |

#### buffer/ — 缓冲池管理

| 文件 | 功能 | 说明 |

| `BufferMgr.java` | 缓冲池管理器 | 管理内存缓冲区，实现 LRU 替换策略 |
| `Buffer.java` | 单个缓冲区 | 封装一个内存页，支持脏页标记和引用计数 |
| `BufferAbortException.java` | 缓冲区异常 | 缓冲区分配超时抛出 |

#### log/ — 日志管理

| 文件 | 功能 | 说明 |
|------|------|------|

| 文件 | 功能 | 说明 |

#### tx/concurrency/ — 并发控制

#### tx/recovery/ — 崩溃恢复

| `RollbackRecord.java` | 事务回滚记录 | |

### 模块暴露接口

```java
// 存储系统向上提供的核心服务
public class FileMgr {
    Page read(BlockId blk);
    void write(BlockId blk, Page page);
    boolean isNew();
}

public class BufferMgr {
    Buffer pin(BlockId blk);
    void unpin(Buffer buf);
}

public class Transaction {
    Page getPage(BlockId blk);
    void pin(BlockId blk);
    void unpin(BlockId blk);
    void commit();
    void rollback();
    void recover();
}
```

## 5. 模块依赖关系

```
成员A (编译器)                    成员B (引擎)                    成员C (存储)
─────────────                    ──────────                    ──────────
parse/*                          query/*                      file/*
plan/*                           materialize/*                buffer/*
opt/*                            multibuffer/*                log/*
index/planner/*                  metadata/*                   tx/*
query/* (常量/表达式)              record/*                     tx/concurrency/*
                                 index/query/*                tx/recovery/*
                                 index/btree/*
                                 index/hash/*
                                 jdbc/*
                                 server/*
```

### 依赖方向

```
编译器 ──依赖──→ query/ (Constant, Expression, Predicate, Term)
引擎   ──依赖──→ 编译器 (Plan, Scan 接口)
引擎   ──依赖──→ 存储 (FileMgr, BufferMgr, Transaction)
存储   ──被依赖──→ 引擎, 编译器 (通过 Transaction)
```

## 7. 开发顺序建议

### 第一阶段：各模块独立运行

| 阶段 | 成员A | 成员B | 成员C |
|------|-------|-------|-------|
| 1 | 跑通 Parser 测试 | 跑通 Scan 测试 | 跑通 FileMgr 测试 |
| 2 | 实现 CREATE TABLE | 实现 TableScan | 实现 BufferMgr |
| 3 | 实现 SELECT 语句 | 实现 MetadataMgr | 实现 LogMgr |
| 4 | 实现 INSERT/DELETE | 实现 JDBC 接口 | 实现 Transaction |

### 第二阶段：模块集成

| 阶段 | 工作内容 |
|------|---------|
| 5 | 编译器 + 引擎集成（Plan → Scan） |
| 6 | 引擎 + 存储集成（Scan → BufferMgr → FileMgr） |
| 7 | 三方联调（SQL → 解析 → 计划 → 执行 → 存储） |

### 第三阶段：高级功能

| 阶段 | 工作内容 |
|------|---------|
| 8 | 索引支持（B+树） |
| 9 | 查询优化器 |
| 10 | 并发控制与事务 |

## 8. 通信约定

### 接口变更流程

1. 修改接口前在群里通知
2. 提供修改后的接口定义
3. 确认其他模块无影响后提交
4. 更新本文档

### 分支管理

- `main` — 稳定版本
- `develop` — 开发主线
- `feature/compiler` — 编译器开发分支
- `feature/engine` — 引擎开发分支
- `feature/storage` — 存储开发分支

### 代码规范

- 类名：大驼峰 `CamelCase`
- 方法名：小驼峰 `camelCase`
- 常量：全大写 `MAX_SIZE`
- 包名：全小写 `simpledb.parse`
- 每个文件头部注明作者和模块
