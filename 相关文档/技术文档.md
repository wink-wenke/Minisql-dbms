## 1. 项目概述

### 1.1 项目定位

本项目不是单纯的编译器实验，而是一个**完整的数据库管理系统**。学生需要将三门核心课程的知识贯通融合：

| 课程知识 | 对应模块 | 核心贡献 |
|---------|---------|---------|
| **编译原理** | SQL编译器 | 词法分析、语法分析、语义分析、执行计划生成 |
| **操作系统** | 存储系统 | 页式存储、缓冲池管理、内存与磁盘的调度 |
| **数据库** | 数据库引擎 | 执行算子、存储引擎、系统目录、数据持久化 |

**核心主线**：让学生真正体验"从SQL语言 → 执行计划 → 数据页"的完整系统链路，把编译原理、操作系统和数据库真正贯通起来。

### 1.2 MiniSQL 功能范围

**核心SQL子集（必做）**：

```sql
CREATE TABLE student(id INT, name VARCHAR, age INT);
INSERT INTO student(id, name, age) VALUES (1, 'Alice', 20);
SELECT id, name FROM student WHERE age > 18 AND id != 3;
DELETE FROM student WHERE id = 1;
```

**必做语言能力**：`CREATE TABLE` / `INSERT INTO` / `SELECT` / `DELETE FROM`、`WHERE` 条件、比较运算、`AND` / `OR` / `NOT`、括号

**扩展能力**（可选）：`UPDATE` / `ORDER BY` / `GROUP BY` / `JOIN`、算术表达式、`NULL`、更多数据类型

## 2. 模块一：SQL编译器（编译原理）

### 2.1 模块职责

SQL编译器是数据库的前端，负责将用户输入的SQL文本转换为数据库引擎可执行的逻辑计划。它对应编译原理课程中的完整编译流水线。

### 2.2 词法分析器 (Lexer)

#### 2.2.1 功能与接口

- **输入**：SQL字符流（文件或标准输入），支持多条SQL（以`;`分隔），保留行号列号
- **输出**：Token Stream，每个Token为四元组 `<TokenType, Lexeme, Line, Column>`

#### 2.2.2 Token类型

| Token类型 | 示例 | 说明 |
|-----------|------|------|
| `KEYWORD` | `SELECT`, `FROM`, `WHERE`, `CREATE`, `TABLE`, `INSERT`, `INTO`, `VALUES`, `DELETE` | 大小写不敏感 |
| `IDENTIFIER` | `student`, `age`, `user_name` | 表名、列名 |
| `CONST` | `20`, `3.14`, `'Alice'`, `'Tom''s book'` | 整数、浮点、字符串 |
| `OPERATOR` | `=`, `!=`, `>`, `>=`, `<`, `<=`, `+`, `-`, `*`, `/` | 比较与算术 |
| `DELIMITER` | `(`, `)`, `,`, `;` | 分隔符 |

#### 2.2.3 核心数据结构

```
Token {
  type: TokenType
  lexeme: string       // 实际值
  line: int            // 行号（从1开始）
  column: int          // 列号（从1开始）
}
```

#### 2.2.4 实现流程

```
输入字符流 → 跳过空白 → 跳过注释 → 读取字符 → 分类处理
                                              │
                         ┌────┬────┬────┬────┬────┐
                         ▼    ▼    ▼    ▼    ▼    ▼
                       字母  数字   '   运算符 分隔符 非法
                         │    │    │    │    │    │
                         ▼    ▼    ▼    ▼    ▼    ▼
                       ID/  数字  字符串 多字符 单字符 ERROR
                       KW   常量  常量  运算符 分隔符
```

#### 2.2.5 难点处理

| 难点 | 处理策略 |
|------|---------|
| 注释 `--` / `/* */` | 遇到`--`跳到行末；遇到`/*`跳到`*/` |
| 多字符运算符 `>=` `<=` `!=` | 读取首字符后peek下一个，合并或单独输出 |
| 字符串转义 `'Tom''s book'` | 连续两个`''`转义为一个`'` |
| 大小写 | 关键字匹配时转大写，字符串内容保持原样 |
| 非法输入 `@`、未闭合字符串 | 返回ERROR Token + 位置 + 原因，**不得崩溃** |

### 2.3 语法分析器 (Parser)

#### 2.3.1 功能与接口

- **输入**：Token Stream
- **输出**：AST（抽象语法树）

#### 2.3.2 文法设计（必须提交 grammar.md）

**SQL语句文法**：
```bnf
statement       -> create_stmt | insert_stmt | select_stmt | delete_stmt ;

create_stmt     -> CREATE TABLE IDENTIFIER '(' column_def { ',' column_def } ')' ';' ;
column_def      -> IDENTIFIER type ;
type            -> INT | VARCHAR ;

insert_stmt     -> INSERT INTO IDENTIFIER '(' id_list ')' VALUES '(' value_list ')' ';' ;
id_list         -> IDENTIFIER { ',' IDENTIFIER } ;
value_list      -> value { ',' value } ;
value           -> CONST ;

select_stmt     -> SELECT select_list FROM IDENTIFIER where_opt ';' ;
select_list     -> '*' | IDENTIFIER { ',' IDENTIFIER } ;
where_opt       -> WHERE expression | ε ;

delete_stmt     -> DELETE FROM IDENTIFIER where_opt ';' ;
```

**表达式文法（体现优先级）**：
```bnf
expression      -> or_expr ;
or_expr         -> and_expr { OR and_expr } ;
and_expr        -> not_expr { AND not_expr } ;
not_expr        -> NOT not_expr | comparison ;
comparison      -> primary [ comp_op primary ] ;
comp_op         -> '=' | '!=' | '>' | '>=' | '<' | '<=' ;
primary         -> IDENTIFIER | CONST | '(' expression ')' ;
```

**优先级**（从高到低）：括号 > NOT > 比较运算 > AND > OR

#### 2.3.3 AST节点设计

**Statement节点**：
```
CreateTableStmt { tableName, columns: [{name, type}] }
InsertStmt      { tableName, columns: [string], values: [Expression] }
SelectStmt      { columns: [string]|'*', tableName, where: Expression|null }
DeleteStmt      { tableName, where: Expression|null }
```

**Expression节点**：
```
BinaryExpr      { op, left: Expression, right: Expression }
UnaryExpr       { op, operand: Expression }
IdentifierExpr  { name: string }
LiteralExpr     { value: any, type: DataType }
```

**AST示例**：
```sql
-- 输入：WHERE a = 1 OR b = 2 AND c = 3
-- AST（AND优先级高于OR）：
        OR
       /  \
    a=1    AND
          /  \
       b=2    c=3
```

**设计要点**：AST不能做成Token的简单堆叠，必须体现语法结构和优先级。

#### 2.3.4 实现策略

| 策略 | 优点 | 要求 |
|------|------|------|
| **LL(1)表驱动** | 与课程理论直接对应 | 文法改造、FIRST/FOLLOW、预测分析表、语法栈、AST动作 |
| **递归下降** | 结构清晰、易构造AST | 每个非终结符对应函数、正确处理优先级、明确lookahead、错误恢复 |
| **LR/工具生成** | 可作为挑战项 | 能解释状态/冲突、不能只调用库后视为完成 |

#### 2.3.5 错误诊断

**必须实现三要素**：
```
SyntaxError at line 3, column 19
unexpected token: ';'
expected: IDENTIFIER | CONST | '(' | NOT
```

- **位置**（line + column）：定位到错误Token
- **实际符号**（unexpected token）：告诉用户看到了什么
- **期望集合**（expected tokens）：给出修复线索

### 2.4 语义分析器 (Semantic Analyzer)

#### 2.4.1 功能与接口

- **输入**：AST + Catalog
- **输出**：验证后的AST（类型标注、名字绑定）

#### 2.4.2 Catalog设计

Catalog是SQL编译器的"符号表"，对应编译原理中的Symbol Table：

```
Catalog {
  tables: Map<string, TableInfo>
}
TableInfo { name, columns: [{name, type}] }
```

**核心接口**：`createTable` / `findTable` / `findColumn` / `getType`

**模式目录示例**：
```
Catalog
├── student: id(INT), name(VARCHAR), age(INT)
└── course:  cid(INT), title(VARCHAR), score(INT)
```

#### 2.4.3 语义检查项

| 检查项 | 错误示例 |
|--------|---------|
| 表存在性 | `SELECT * FROM nonexistent` → 表不存在 |
| 列存在性 | `SELECT score FROM student` → 列不存在 |
| 名字绑定 | `age` → 绑定到 `student.age` |
| 类型一致性 | `age + 'abc'` → INT与VARCHAR不能运算 |
| INSERT匹配 | 列数/顺序/值类型必须一致 |

#### 2.4.4 类型系统

| 表达式 | 结果 |
|--------|------|
| `INT + INT` / `INT - INT` / `INT * INT` | `INT` |
| `INT > INT` / `INT = INT` | `BOOL` |
| `VARCHAR = VARCHAR` | `BOOL` |
| `BOOL AND BOOL` / `BOOL OR BOOL` / `NOT BOOL` | `BOOL` |
| `INT + VARCHAR` | **ERROR** |

**设计建议**：类型规则集中管理，不散落在各处的if/else中。

#### 2.4.5 错误报告

语义错误同样要求"类型 + 位置 + 原因"：
```
SemanticError at line 3, column 11
operator '+' cannot be applied to INT and VARCHAR
```

### 2.5 执行计划生成与优化

#### 2.5.1 Logical Plan 节点

| 节点 | 功能 |
|------|------|
| `CreateTable` | 创建表与注册元数据 |
| `Insert` | 向目标表写入记录 |
| `SeqScan` | 顺序扫描表记录 |
| `Filter` | 执行WHERE条件 |
| `Project` | 返回SELECT指定列 |

#### 2.5.2 转换规则

- `FROM` → `SeqScan`（数据源）
- `WHERE` → `Filter`（过滤条件）
- `SELECT`列 → `Project`（投影列）

**示例**：
```sql
SELECT name FROM student WHERE age > 18;
-- → Project[name] → Filter[age > 18] → SeqScan[student]
```

#### 2.5.3 规则式优化

| 优化规则 | 示例 |
|---------|------|
| 常量折叠 | `age > 10 + 8` → `age > 18` |
| 布尔化简 | `x AND TRUE` → `x` |
| Projection Pruning | 只保留查询需要的列 |
| Predicate Pushdown | 有JOIN时尽量提前过滤 |
| 冗余节点消除 | `Project[*]` / 恒真`Filter`可删除 |

**优化前后对比**：
```sql
-- 输入：SELECT name FROM student WHERE 1 = 1 AND age > 10 + 8;
-- 优化前：Project[name] → Filter[1=1 AND age>10+8] → SeqScan[student]
-- 优化后：Project[name] → Filter[age > 18] → SeqScan[student]
```

**验证重点**：规则正确、前后结构可验证、结果语义等价。

## 3. 模块二：数据库引擎（数据库）

### 3.1 模块职责

数据库引擎是整个系统的核心执行层。它接收SQL编译器生成的Logical Plan，调用存储系统完成实际的数据操作，并维护系统目录（元数据）。

### 3.2 执行引擎

#### 3.2.1 执行算子

| 算子 | 功能 | 输入 | 输出 |
|------|------|------|------|
| `CreateTable` | 创建表与注册元数据 | 表名+列定义 | 创建结果 |
| `Insert` | 向目标表写入记录 | 表名+值列表 | 写入结果 |
| `SeqScan` | 顺序扫描表记录 | 表名 | 记录流 |
| `Filter` | 执行WHERE条件 | 条件+子计划 | 过滤后记录流 |
| `Project` | 返回SELECT指定列 | 列名+子计划 | 投影后记录流 |

#### 3.2.2 执行模型（火山模型）

每个算子实现 `next()` 接口，通过迭代器模型逐行返回结果：

```
Project.next()
  record = Filter.next()
  if record == EOF: return EOF
  return project(record)

Filter.next()
  while true:
    record = SeqScan.next()
    if record == EOF: return EOF
    if evaluate_where(record): return record

SeqScan.next()
  return next_record_from_table()  // 调用存储系统读取下一条记录
```

#### 3.2.3 执行流程示例

**SQL**: `SELECT name FROM student WHERE age > 18;`

```
1. SeqScan 从 student 表读取记录 (1, 'Alice', 20)
2. Filter 检查 age > 18 → true → 通过
3. Project 提取 name → 'Alice' → 返回
4. SeqScan 读取 (2, 'Bob', 19)
5. Filter 检查 age > 18 → true → 通过
6. Project 提取 name → 'Bob' → 返回
7. SeqScan 读取完毕 → EOF → 结束
```

### 3.3 存储引擎

#### 3.3.1 行与页的映射

```
逻辑视图：Record (1, 'Alice', 20)
物理映射：Page 1, Slot 3, Offset 128, Length 24 bytes
寻址公式：record_address = page_start + slot_directory[slot_id] + record_offset
```

#### 3.3.2 磁盘组织

```
表文件 student.dat:
┌──────────┬──────────┬──────────┬──────────┐
│  Page 0  │  Page 1  │  Page 2  │  Page 3  │
│ (Header) │ (Data)   │ (Data)   │ (Data)   │
└──────────┴──────────┴──────────┴──────────┘

每页内部：
┌─────────────────────────────────────────┐
│ Header (16 bytes)                       │
├─────────────────────────────────────────┤
│ Slot Directory (8 bytes × slot_count)   │
├─────────────────────────────────────────┤
│ Record Area (variable)                  │
├─────────────────────────────────────────┤
│ Free Space                              │
└─────────────────────────────────────────┘
```

### 3.4 系统目录（System Catalog）

系统目录维护所有表的元数据，作为特殊表持久化存储：

```
系统目录存储内容：
├── 表信息：表名、列数、每列的名称/类型/长度、记录总数
├── 索引信息（扩展）：索引名、关联表、索引列
└── 统计信息（扩展）：列基数、最小/最大值
```

**核心接口**：`createTable` / `dropTable` / `getTable` / `addColumn` / `listTables`

### 3.5 高级扩展功能

| 功能 | 说明 | 难度 |
|------|------|------|
| 事务管理 | BEGIN / COMMIT / ROLLBACK | 高 |
| 并发控制 | 锁机制（共享锁/排他锁） | 高 |
| 复杂索引 | B+树索引、哈希索引 | 高 |
| 查询优化 | 基于代价的优化（CBO） | 高 |
| 访问控制 | 用户权限管理 | 中 |
| 日志与恢复 | WAL（Write-Ahead Logging） | 高 |
| MVCC | 多版本并发控制 | 高 |

## 4. 模块三：存储系统（操作系统）

### 4.1 模块职责

存储系统是数据库的底层基础设施，对应操作系统课程中的内存管理与I/O管理。它向上为数据库引擎提供统一的数据访问接口，向下管理磁盘页的分配、读写与缓存。

### 4.2 页式存储模型

#### 4.2.1 基本概念

| 概念 | 说明 |
|------|------|
| Page（页） | 存储的基本单位，通常4KB或8KB |
| Page ID | 页的唯一标识符 |
| Page Slot | 页内的记录槽位 |
| Free Space | 页内可用空间 |

#### 4.2.2 页结构

```
┌─────────────────────────────────────┐
│           Page Header              │
│  Page ID | Record Count | Free Ptr │
│  Slot Directory (variable)         │
├─────────────────────────────────────┤
│           Record Area              │
│  Record 1 │ Record 2 │ ...        │
├─────────────────────────────────────┤
│           Free Space               │
└─────────────────────────────────────┘
```

#### 4.2.3 核心接口

| 接口 | 功能 |
|------|------|
| `allocatePage()` | 分配新页，返回PageID |
| `releasePage(pageId)` | 释放页 |
| `readPage(pageId)` | 读取页内容 |
| `writePage(pageId, data)` | 写入页内容 |
| `getFreeSpace(pageId)` | 获取页内可用空间 |

### 4.3 缓冲池管理（Buffer Pool）

#### 4.3.1 功能描述

缓冲池是内存中的页缓存区，用于减少磁盘I/O。这是**操作系统课程中内存管理**的直接应用。

```
┌─────────────────────────────────────────────┐
│              Buffer Pool                    │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐      │
│  │ Frame 0 │ │ Frame 1 │ │ Frame 2 │ ...  │
│  │ Page A  │ │ Page B  │ │ Page C  │      │
│  │ Pin=1   │ │ Pin=0   │ │ Pin=0   │      │
│  │ Dirty=0 │ │ Dirty=1 │ │ Dirty=0 │      │
│  └─────────┘ └─────────┘ └─────────┘      │
│                                             │
│  Replacement Policy: LRU / FIFO            │
│  Hit Statistics: hit_count / total_count   │
└─────────────────────────────────────────────┘
```

#### 4.3.2 替换策略

| 策略 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **LRU** | 替换最久未使用的页 | 命中率高，符合局部性原理 | 实现较复杂 |
| **FIFO** | 替换最早进入的页 | 实现简单 | 可能替换频繁使用的页 |

**LRU实现方式**：
- **时间戳法**：记录每页最后访问时间
- **链表法**：访问的页移到头部，替换尾部
- **Clock算法**：近似LRU，使用引用位和时钟指针

#### 4.3.3 关键机制

```
pin(pageId)        // 固定页，不允许被替换
unpin(pageId)      // 解除固定，允许被替换
markDirty(pageId)  // 标记页已被修改，淘汰时需写回磁盘
getHitRate()       // 返回命中率 = hit_count / total_count
```

#### 4.3.4 日志记录

```
[BufferPool] Page 5 loaded into frame 3
[BufferPool] Page 5 hit (frame 3)
[BufferPool] Page 2 evicted (frame 0, dirty=true, written back)
[BufferPool] Hit rate: 85.7% (6/7)
```

### 4.4 表文件与元数据

#### 4.4.1 表文件组织

```
table_student.dat
├── Page 0: 表头页（元数据）
│   ├── 表名: student
│   ├── 列数: 3
│   ├── 列定义: [{id, INT}, {name, VARCHAR}, {age, INT}]
│   └── 记录数: 100
├── Page 1: 数据页
```

### 5.3 Mock解耦：并行开发的核心机制

每个模块在开发初期使用Mock对象替代尚未完成的依赖模块，实现**零等待并行开发**。

#### 5.3.1 编译器侧Mock（Mock存储系统）

编译器不需要真实存储，只需验证输出的Logical Plan结构正确：

```python
# MockStorage — 编译器测试用
class MockStorage:
    def create_table(self, name, schema):
        print(f"[Mock] CREATE TABLE {name}")  # 仅打印，不实际创建

    def scan_table(self, table):
        return iter([])  # 返回空迭代器
```

#### 5.3.2 引擎侧Mock（Mock编译器和存储）

引擎需要Mock编译器返回固定Plan，Mock存储返回固定数据：

```python
# MockCompiler — 引擎测试用
class MockCompiler:
    def compile(self, sql_text):
        # 返回预设的Logical Plan，不经过词法/语法/语义分析
        return LogicalPlan(node_type="SeqScan", params={"table": "student"})

# MockStorage — 引擎测试用
class MockStorage:
    def scan_table(self, table):
        # 返回预设的测试数据
        return iter([
            Record(fields=[1, "Alice", 20]),
            Record(fields=[2, "Bob", 19]),
        ])
```

#### 5.3.3 存储侧Mock（Mock引擎）

存储系统可以独立测试，不需要引擎：

```python
# 存储系统独立测试，直接调用接口
def test_buffer_pool():
    storage = StorageManager(page_size=4096, buffer_size=10)
    storage.create_table("student", schema)
    storage.insert_record("student", Record(fields=[1, "Alice", 20]))
    records = list(storage.scan_table("student"))
    assert len(records) == 1
```

### 5.4 增量集成：分阶段替换Mock

集成不是一次性完成的，而是**多次增量集成**，每次替换一个Mock，验证通过后再进行下一次。

#### 5.4.1 集成路线图

```
阶段1：各模块独立开发 + Mock测试
  ├── 编译器：用MockStorage测试，验证Plan输出正确
  ├── 引擎：用MockCompiler + MockStorage测试，验证算子逻辑正确
  └── 存储：独立测试，验证读写/缓冲池/替换策略正确

阶段2：编译器 + 引擎 集成
  ├── 替换 MockCompiler → 真实编译器
  ├── 保留 MockStorage（存储尚未集成）
  └── 验证：SQL文本 → Plan → 算子执行（数据为Mock）

阶段3：引擎 + 存储 集成
  ├── 替换 MockStorage → 真实存储
  ├── 编译器已集成
  └── 验证：SQL文本 → Plan → 算子执行 → 真实数据读写

阶段4：全链路集成
  ├── 三模块全部真实连接
  ├── 端到端测试：CREATE → INSERT → SELECT → DELETE
  └── 隐藏测试 + Fuzz测试
```

#### 5.4.2 每次集成的验证清单

| 集成阶段 | 验证内容 | 通过标准 |
|---------|---------|---------|
| 阶段1→2 | 编译器输出的Plan能被引擎正确消费 | Plan结构匹配、节点类型正确 |
| 阶段2→3 | 引擎的算子能正确调用存储接口 | scanTable返回正确记录、insertRecord写入成功 |
| 阶段3→4 | 全链路SQL执行 | CREATE→INSERT→SELECT→DELETE端到端通过 |

#### 5.4.3 集成常见问题与解决

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| Plan节点类型不匹配 | 编译器和引擎对节点命名不一致 | 严格遵守共享接口定义 |
| 数据格式不兼容 | Record字段顺序/类型约定不同 | 使用共享数据结构 |
| Catalog不一致 | 编译器侧和引擎侧各自维护Catalog | Catalog单一数据源，双侧共享 |
| 错误传播断裂 | 模块间错误类型不统一 | 定义统一的错误类型层次 |

## 6. 系统集成：三模块协作

### 6.1 完整数据流

```
SQL文本: "SELECT name FROM student WHERE age > 18;"
    │
    ▼ ──────────────────── 编译原理 ────────────────────
    │
    Lexer    → Token流（13个Token）
    Parser   → AST（SelectStmt节点树）
    Semantic → 验证后AST（名字已绑定，类型已检查）
    Plan     → Logical Plan: Project[name] → Filter[age>18] → SeqScan[student]
    │
    ▼ ──────────────────── 数据库 ──────────────────────
    │
    Optimizer → 优化后Plan（常量折叠、冗余消除等）
    Executor  → 调用SeqScan/Filter/Project算子执行
    │
    ▼ ──────────────────── 操作系统 ────────────────────
    │
    Storage  → SeqScan调用BufferPool读取数据页
             → BufferPool检查缓存，未命中则从磁盘读入
             → 返回记录给Filter算子
             → Filter计算条件，Project投影列
             → 结果返回给用户
```

### 6.2 模块间接口汇总

| 接口 | 调用方 | 被调用方 | 数据格式 |
|------|--------|---------|---------|
| `lex(sql)` | Parser | Lexer | SQL文本 → Token流 |
| `parse(tokens)` | Semantic | Parser | Token流 → AST |
| `analyze(ast, catalog)` | PlanGen | Semantic | AST → 验证后AST |
| `generatePlan(ast)` | Optimizer | PlanGen | AST → Logical Plan |
| `optimize(plan)` | Executor | Optimizer | Plan → 优化后Plan |
| `execute(plan)` | Main | Executor | Plan → 执行结果 |
| `scanTable(table)` | Executor | Storage | 表名 → 记录流 |
| `insertRecord(table, record)` | Executor | Storage | 表名+记录 → 写入结果 |
| `readPage(pageId)` | BufferPool | Disk | PageID → PageData |
| `writePage(pageId, data)` | BufferPool | Disk | PageID+Data → 写入 |

### 6.3 Catalog 的双重角色

Catalog在系统中扮演两个角色：
- **编译器侧**：作为"符号表"，服务于语义分析（名字绑定、类型检查）
- **引擎侧**：作为"系统目录"，服务于执行引擎和持久化（元数据管理）

## 附录：LL(1) 文法基础回顾

### 消除左递归

```
原始（左递归，会无限循环）：  E -> E + T | T
消除后：                     E  -> T E'
                            E' -> + T E' | ε
```

### FIRST / FOLLOW / Predict Table

| 概念 | 定义 |
|------|------|
| FIRST(α) | α可能推导出的第一个终结符集合 |
| FOLLOW(A) | 非终结符A之后可能紧跟的终结符集合 |
| 预测分析表 | 由栈顶非终结符 + lookahead唯一选择产生式 |

**关键理解**：分析表最终服务于AST构造，而不是只打印"语法正确"。
